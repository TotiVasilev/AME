AME v0.7.0 — Документи: accountant-facing workflow rebuild
============================================================

IMPORTANT
---------
This is a functional development update, NOT a production-ready replacement
for VIVA and NOT certified for Bulgarian tax filings. Use fictitious companies
and records until your accountant approves the workflows and official formats.

What changed
------------
- The dashboard's "Документи" and top menu "Въвеждане на документи" now open a
  distinct document-entry window patterned on the VIVA screenshot supplied.
- There are three modes: Свободни операции, Покупки, Продажби.
- Header fields include document number, date, registration date, explanation,
  deal reference, counterparty selected by name/EIK.
- Debit and credit are presented as two separate tables, with account, analytical
  reference (Партида), quantity, and amount.
- Multiple rows can be added manually on either side; the totals remain visible.
- On purchases/sales, use a saved counterparty, select an expense/revenue account
  and payment method, choose VAT treatment and click "Предложи записи".
- Automatic VAT supports 20%, 9%, 0% as arithmetic choices, including calculating
  backwards from a VAT-inclusive total. It does NOT choose the legally correct
  VAT rate, eligibility, tax credit or reporting column for you.
- "F8 В брой" selects cash payment (501); refresh the proposed entries after.
- "F5 Осчетоводи" validates, confirms, and saves document metadata plus a
  balanced journal entry atomically. The document appears in Опис and reports.
- "Опис" now includes counterparty, type, search and an Open button/double click.
  New-format documents open for editing in Документи; older operations open in
  the retained manual journal editor.
- The old journal is still available from "Ръчен журнал" on the dashboard.
- A two-line self-cancelling debit+credit on the same account cannot be posted.
- The 144-entry starter Сметкоплан and all other previously implemented modules
  are retained. No company database is deleted or replaced.

Limits you must know
--------------------
- VAT posting accounts 4531/4532 and default 601/703, 401/411, 501, 503 are
  suggestions requiring review. Actual VAT treatment depends on the transaction.
- This is a general document accounting editor, NOT a complete multi-item sales
  invoice issuer. The separate "Фактуриране" module remains excluded as requested.
- Analytical references (Партида) and quantities are stored with journal lines,
  but the existing reports do not yet aggregate by these analytical dimensions.
- Existing historical journal entries are NOT silently migrated into new document
  metadata. They remain editable through the old journal screen except where
  pre-existing invoice/payment protection applies.
- Audit table currently records metadata edit events; it is NOT a comprehensive
  immutable legal audit trail.
- No official НАП TXT, D1/D6, employee-record XML, or verified payroll/annual tax
  calculation is generated by this update. Prior workbenches remain as they were.
- Currency minor units reflect your company settings; confirm dates and currency
  treatment for historical transactions with the accountant.

Installation (Windows 11 development, Windows 10 target)
------------------------------------------------------
1. Close AME. Commit your current source in VS Code Source Control.
2. Back up: %LOCALAPPDATA%\AME (including the entire companies folder).
3. Unzip this package into C:\Users\todor\Documents\AME, replacing only source
   files and CMakeLists.txt. DO NOT delete third_party, .git or your databases.
4. Open existing Developer Command Prompt:

   cd /d C:\Users\todor\Documents\AME
   cmake -S . -B build-v070 -A Win32
   cmake --build build-v070 --config Release
   build-v070\Release\AME.exe

Acceptance test (use fictional data)
-----------------------------------
A. Select Test Company, open Сметкоплан and check 601, 401, 4531, 411,
   703, 4532 exist and are active.
B. Open "Документи", click "Контрагенти..." and create Supplier Test and
   Customer Test (use fake identifiers). Return and select the supplier by name.
C. Choose Покупки, number BUY-TEST-01, current valid date, description "Материали",
   base 100.00, VAT rate 20%, expense account 601, method Неплатено.
   Click "Предложи записи": Debits 601:100 and 4531:20; Credit 401:120.
   Press F5 and confirm. Observe success and document ID.
D. Open Опис: purchase should appear with counterparty, total 120.00.
   Double-click the purchase, edit its description and F5 again; no duplicate.
E. New purchase with SAME supplier/number/year must be rejected atomically.
F. Open Документи > Свободни операции; try 501 debit 90 and 501 credit 90.
   F5 should reject this self-cancelling entry.
G. For a sale: customer Test, SALES-TEST-01, 300.00 base, 20% VAT,
   revenue account 703, method Неплатено. Proposal: Debit 411:360,
   Credit 703:300 and 4532:60. Confirm and find it in Опис.
H. Existing legacy journal records (e.g. TEST-001) should still appear in Опис.
   Opening them uses the old manual journal, not the new document editor.
I. Close/reopen AME and confirm purchase/sale entries and edit persisted.
J. Only on a THROWAWAY database, test a closed financial year is locked.

If your accountant cannot complete C-I without help, please send us the exact
screen and step that blocked them. This is an acceptance test, not compliance.

Verification performed on source package
----------------------------------------
- document_store.cpp compiled with g++ -std=c++14 -Wall -Wextra -pedantic.
- SQLite in-memory tests covered insert/edit/read, duplicate rollback,
  generated journal balances, legacy entry retention, same-account rejection,
  date checks, VAT gross-split rounding, closed-year refusal and edit protection.
- New Win32 files passed a syntax-only check against minimal Win32 declaration
  stubs. This is NOT the same as compiling against real Windows headers.
- Full MSVC build, real Windows interface, and accountant review remain untested.
